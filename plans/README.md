## Findings considered and rejected

- **RTL panel direction**: The panel opens from the left edge in an RTL app. In RTL, the left edge is the "end" side — this is actually correct for a navigation drawer. The panel toggle uses `chevron-forward`/`chevron-back` icons which adapt to RTL. No fix needed.
- **Bottom sheet migration**: The control panel is a full-height sidebar. The mobile-native pattern would be a bottom sheet (half/full sheet). This is addressed by plan 009 (Google Maps-style redesign) which replaces the sidebar with @gorhom/bottom-sheet.
- **Persistent GPS tracking**: The current GPS is one-shot. Adding `watchPositionAsync` with a toggle is a feature enhancement, not a UI fix. Noted as future work.
- **Neshan API migration**: Replacing Nominatim/OSRM with Neshan for better Iran coverage. Out of scope — current free APIs work. Noted in plan 001 index.
- **Test infrastructure**: No Jest/Vitest configured. Adding tests is a separate initiative. Verification in these plans is via lint + typecheck + manual.
- **Dark mode support**: Significant effort for a color-themed app. Deferred to future work.
- **Orientation lock**: Locking to portrait is common for map apps but not strictly necessary since the layout already works in both orientations. Low priority.
- **Concurrent Promise.all for OSRM routes**: Rejected per plan 001 notes — OSRM public demo server 429s concurrent requests.
- **Stale closure in SearchBar debounce**: The `handleSearch` callback has `[]` deps but receives `value` as a parameter from `onChangeText`, so it's not actually stale. The search works correctly.
- **Phase 2 collections in 011**: Company, Fleet, Staff, Rating, Payment, VehiclePosition, Notification, AuditLog, SystemSettings. The RFP lists them, but Phase 1 booking does not need them. Adding them now would freeze field names before the booking flow exists.
- **Email-first User identity**: Rejected. Iran-first identity is phone (`User.phone` unique). Email is optional profile text. No Firebase uid.
- **Embedding GPS points on Shipment / ShipmentEvent**: Rejected. Live GPS is Phase 2; 011 only allows an optional GeoJSON point on a discrete event (checkpoint / customs).
- **Password / otpHash on User in 011**: Rejected. Auth is the next slice; 011 only reserves `phone` + `phoneVerifiedAt`.
- **OTP / password columns in 013**: Rejected. V6 moved SMS Phone OTP to Phase 2 §9. 013 only adds `Cargo.transportMode`.
- **SMS gateway / Kavenegar / Twilio in 014**: Rejected. V6 Phase 2 §9. 014's sender logs in dev (with code) and uses `OTP_FIXED_CODE` in test; production persists the challenge and logs phone only, no SMS SDK.
- **Cookies + CORS lock-down in 014**: Rejected. 010 left CORS `origin: true` until cookies exist. 014 uses HTTP Bearer JWT so Expo can store a token later without a cookie domain.
- **otpHash / password on User in 014**: Rejected. Challenges live in `OtpChallenge`; User keeps `phone` + `phoneVerifiedAt` only.
- **Separate /register vs /login in 014**: Rejected. Same two endpoints (`request-otp` / `verify-otp`) upsert the cargo_owner user. Profile PATCH is a later slice.
- **Returning the OTP in the JSON body for tests in 014**: Rejected. Tests set `OTP_FIXED_CODE=123456`.
- **Refresh tokens / logout denylist / Redis in 014**: Rejected. One HS256 JWT, 7d. Fail closed if `JWT_SECRET` is missing.
- **Per-mode cargo spec columns in 013** (`containerNumber`, `imoNumber`, `awbNumber`, `wagonId`, Mixed `modeDetails`): Rejected. V6 names five register/manage surfaces; SRS locks extra attributes. Discriminator first.
- **Vehicle types for sea/air/rail in 013**: Rejected. `Vehicle` is a road asset (plate + `vehicleType`). Cargo mode lives on `Cargo`, not `Vehicle`.
- **Phase 2 collections in 013**: Same as 011 — Company, Fleet, Rating, Payment, GPS, Notification, AuditLog stay parked.
- **Copying RFP §5/§8/§9 (SOW, Play Store publish, NDA, SLA) into the feature list (012)**: rejected — contractor process, not app features.
- **Moving GPS / companies / payments into Phase 1 because the RFP lists them in 4.2 (012)**: rejected — RFP 4.6 allows phasing; existing V5 split stays. 012 only ensures they remain named (already true in Phase 2).
